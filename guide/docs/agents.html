Agents

Background agents for big jobs, the critters that show them, several jobs at once, Claude Code and Codex in the notch, and the ChatGPT and Claude apps.

Agents

For big jobs (research, long documents, code, websites) Mint hands the work to an agent and keeps talking with you. You hear back when it's done.

AstraResearch: searches, reads, cross-checks, writes a sourced brief
LunaCode: plans and writes complete, runnable files
SageWriting: long documents, reports and PDFs
CodexBuilds websites and apps in OpenAI Codex, and checks them
  • have Astra research the best mechanical keyboards
  • ask Codex to make a tiny hello-world page
  • how's Luna doing?
  • tell Luna to use pytest
  • stop all agents
  • create an agent called Nova that writes tweets
Teams, folders and limits

An agent can bring in teammates when their specialty helps (Sage asks Astra for research) and reports back for all of them. Each works in its own folder under ~/Documents/Mint/agents. Up to six at once; stopping the lead stops its helpers. Finished work goes into Mint's memory.

The critters

Each agent is a little critter that lives in a toy box beside the orb. What it does tells you what the agent is doing.

The critterMeans
Pops out with sparklesAn agent started
A “…” or a tool in its bubbleThinking, or searching, reading, writing
A “?” and a hopIt has a question: click it
A somersault and confettiFinished; it hops back into the box
A rain cloud, or a startled “!”Failed, or stopped

Hover to see what one is doing, click for a reaction, right-click to stop it. Say put on a show and the whole family performs:

Several things at once

Give Mint a job, then another, then ask a quick question. The jobs run side by side in the background, the question is answered right away, and each job tells you when it's done. Nothing you started is dropped because you said something new.

  • research the best standing desks and put it in a note
  • also tidy my Downloads folder
  • meanwhile draft a reply to Priya
  • what are you working on?
  • make the desk one shorter
  • stop the Downloads job
  • stop all jobs

How it decides. Quick things - a question, one click, opening an app - Mint just does. Anything longer that you don't need to watch, or anything new you ask while it's busy (“also…”, “meanwhile…”), becomes a background job: Mint says it's on it and stays free to talk. A job works with Mint's own tools - the web, your files, Mail, Calendar, Notes, apps on the Mac - in its own context, so jobs never mix each other up.

The screen takes turns. Jobs that search, read or write files and mail run truly in parallel. Clicking and typing need the screen, so jobs share it: a job keeps it for its consecutive steps, then the next one goes; your own request always goes first; and a job never clicks or types while you are typing - it waits for you to pause.

Never thrown away. If one of Mint's own steps takes long, or you start talking while it's running, it carries on in the background instead of being cancelled, and Mint is told when it ends, so nothing is done twice. Results come when Mint is quiet, never over your words or its own. In the notch, jobs show in the Agents tab next to Claude Code and Codex, with their steps live; reply to a job from there to change it or answer its question. A job that needs something asks you aloud (or on Telegram when you're away).

Stop. “Stop” stops what Mint is doing in front of you, including a job that is clicking at that moment; jobs working off-screen carry on, and Mint says which. “Stop all jobs” or “stop the Downloads job” stops those. Deleting or changing anything still needs your yes (see the guard). Up to four jobs run at once; more wait their turn.

Claude mode: your coding agents in the notch

While Claude Code or Codex works, the notch shows it live: what it reads, the diff it writes, the commands it runs and how they went. When it needs your OK, the notch opens with Allow and Deny. When it's done, Mint hops and shows what it did.

  • Claude mode
  • show my agents
  • what is Claude Code doing?
  • is Codex done?
  • tell Claude to push
  • turn off Claude mode

Nothing to set up to watch. Claude Code (in a terminal, VS Code or the Claude app's Code tab) and Codex (the CLI or the Codex app) write every session to their own logs on your Mac, and Mint reads them as they grow. As soon as a session starts, Claude's sparkle turns slowly in the notch's right wing (Codex's is violet); it pulses amber when the agent waits for you, and turns into a green tick when it finishes. Click the notch or the sparkles button in the small row to open the Agents tab:

  • Left: Mint's face living what the agent does (busy while it works, eyes up while it thinks, amber hops while it waits for you, a starry hop when it's done, a shake if it fails), the project, the session's name and its last steps, each with a spinner, a tick or a cross. The running step shimmers; a new one slides in from below.
  • Right: what matters now: the lines it read, the diff it made (written in line by line, red out, green in), the command and its output (passing tests in green), its to-do list, the question it asks you, or its final answer, with how long it took and how many edits and commands.
  • ‹ › switches between sessions; ↗ or Open brings that session's own window forward: the exact Terminal or iTerm tab it runs in, VS Code, or the Claude or Codex app.

Approve from the notch (Claude Code). Settings ▸ Appearance & Sound ▸ Claude mode ▸ Connect Claude Code adds one small hook to Claude Code's settings (it shows you exactly what before writing, and keeps a backup of ~/.claude/settings.json). From then on, when Claude Code asks to run a command or edit a file, the notch opens on the request with Allow, Always allow (adds Claude Code's own suggested rule, like Bash(npm test:*)) and Deny. The terminal still asks as usual and whichever you answer first counts, so nothing ever waits on Mint; if Mint isn't running, Claude Code just asks in the terminal. Disconnect takes out only Mint's entries.

Small or full. The minimize button folds the Agents tab into one line: Mint's face, the project with a live clock (Working · 1:24), the step it's on (or Allow and Deny, or its answer) and a dot per step; the expand button brings the whole view back. When it opens by itself (an agent finished or needs you) it opens small. Whichever app you're in comes first: in the Claude app, a terminal, VS Code or Codex, the notch shows that app's session, even when it's idle.

From your phone (Telegram). While you're away from the Mac, your agents message you on Telegram: wants to run npm test with ✅ Allow, ♾ Always and ⛔ Deny; asks: which branch?; is done with what it did. Reply to one of those messages (push, use main) and Mint types your words into that session - its Terminal or iTerm tab, or the Claude or Codex app - and tells you when it's done again. /agents lists them all with a 💬 to talk to each, 📸 shows the screen. You can also just say it: tell Claude in korus to push. Only your paired Telegram account can do this, never in read-only mode, and everything is in the remote log. Agents running in VS Code's terminal, Ghostty or Warp can be watched and approved, but not typed into yet; the Claude and Codex apps need the Mac awake and unlocked to type.

Without the notch (orb mode), the same view comes up as a card by the orb when an agent needs you or finishes. Settings ▸ Appearance & Sound ▸ Claude mode: Auto (shows sessions while they work), Always on, or Off; open when an agent needs you; show the summary when it finishes.

What Mint reads from the logs stays on your Mac and is only shown to you; nothing in a session is ever taken as an instruction. Only your click on Allow approves anything - Mint never approves by itself, not even if you ask it by voice.

Did the agent really do it? Checks on its work

An agent saying “Done, all tests pass” isn't proof. Mint reads what really happened in Claude Code's and Codex's own logs: every test run's result from its output, the files it changed, the risky steps. Ask, and you get the evidence, not the agent's word.

  • did Claude's tests pass?
  • did Codex break anything?
  • what did my agents do today?
  • recap what Claude just did
  • how much Codex do I have left?
  • hand this to Codex

Tests, read from their output. pytest, unittest, jest, vitest, mocha, node:test, go, cargo, dotnet, Maven, Gradle, PHPUnit, RSpec, Swift and more: Mint reads the summary itself (2 of 48 failed - test_total: expected 3, got -1) and when it ran. A run where no test actually ran, the output was cut with | tail, or the exit code and the output disagree reads as unclear, never as passed. Change a file after the tests pass and Mint says so: changed invoice.ts since, so the latest code isn't tested. A step that failed and then worked says fixed on try 2.

Worth a second look. Mint flags .env or key files changed, a force-push, git reset --hard, rm -rf, curl | sh, the same command failing three times, a test changed to pass while it was failing (an assertion taken out, a skip added, an expected value changed), and two agents changing the same file within minutes. These show in the notch, in the answer when you ask, and under the agent's done message on Telegram (✅ tests passed · ⚠️ not tested since the last change · 🚩 changed .env).

Today and recaps. Mint keeps a week of finished requests on your Mac (what you asked, the files, how the tests stood, what it said at the end), so what did my agents do today? is a quick spoken standup and recap tells you the last request. Hand-off: hand this to Codex (or Claude Code, or Gemini CLI) writes a note with the ask, what was done, the files, the failing test's output and what's left on its plan, then opens a Terminal window in the same folder that starts the other agent on it.

Usage limits. Codex's 5-hour and weekly limits come straight from its logs. Claude Code gives its limits only to a status line, so Settings ▸ Appearance & Sound ▸ Claude mode ▸ Show Claude's usage limits sets a small one that saves them for Mint and still shows your own status line (it shows what it will change first, and keeps a backup).

Send Claude back to fix failing tests (optional, off by default; needs Connect Claude Code). When Claude tries to finish, commit or push while its tests fail, weren't run after its last change, or pass only because a test was weakened, it's told why and keeps working, at most twice per request; after that it may stop and you're told. A request that changed no code, a project without tests, and failures that were there before it changed anything are never held up. With Claude Code connected, Claude Code also asks you before editing a file another agent changed in the last few minutes.

Let agents ask Mint. Settings ▸ Appearance & Sound ▸ Claude mode ▸ Let agents ask Mint connects Claude Code or Codex to Mint as a read-only MCP server, so the agent itself can call check_my_work before it says “done” and gets the same evidence: Not done yet: you changed calc.py after the last test run… Run the tests again, then Looks ready once they pass. It also offers test_status, recap, today, risky_steps, handoff_note, usage_limits and agents_now. Mint doesn't have to be open, and nothing is changed or sent anywhere. For any other MCP client, python -m mint.tools.agent_mcp --config run with Mint's own Python prints the entry to add.

Only what the agent ran itself counts, and everything is read from logs on your Mac: nothing is sent anywhere, apart from what you ask about out loud. Settings ▸ Appearance & Sound ▸ Claude mode ▸ Check agents' work turns it all off. Rules adapted from dotpals (MIT).

ChatGPT and Claude

Mint can use the ChatGPT and Claude desktop apps for you: ask something, read the answer back, see whether they are still working, and tell you when they finish.

  • ask ChatGPT to outline a talk on local-first apps
  • what did ChatGPT answer?
  • is Claude still working?
  • open my Task auditor session in Claude
  • tell me when Claude is done
  • stop ChatGPT

It checks the prompt landed in the app's message box before pressing Send once, and it only sends when you asked it to. Answers are read to you as quotes: Mint never takes instructions from them. For Claude, Mint works in Claude Code sessions; the Chat view is only read, and only when you ask for it.
